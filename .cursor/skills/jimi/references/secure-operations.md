# 安全工作规范（核心文档）

> 本文件是 jimi 技能包的**最高优先级参考**。所有安全相关工作必须遵循。

## 一、工作原则

1. **授权第一** — 只操作自有资产，书面授权范围内行动
2. **证据优先** — 无动态验证，不报告漏洞
3. **诚实边界** — 架构无 sink 则不捏造 Critical
4. **秘密不入库** — 密码、Key、Token 永不提交 git
5. **快速闭环** — 发现 → 修复 → 复测 → 报告

## 二、每日安全工作流

```
开始工作
  ↓
确认目标在授权范围内？
  ├─ 否 → 停止，拒绝操作
  └─ 是 ↓
读取 SKILL.md + methodology.md
  ↓
执行任务（开发 / 审计 / 部署）
  ↓
涉及安全变更？→ 动态验证
  ↓
提交代码 + 更新报告
  ↓
结束
```

## 三、密钥与访问安全

| 类型 | 存放位置 | 禁止 |
|------|----------|------|
| TONAPI_KEY | `server/.env` | 写入 client 或 git |
| BOT_TOKEN | `bot/.env` | 写入聊天记录 |
| SSH 密码 | 仅用户本机 | 写入仓库任何文件 |
| root 访问 | SSH Key 优先 | 长期密码登录 |

**立即轮换条件：** 密码出现在对话、截图、或公开仓库中。

## 五、渗透测试工作规范

### 必须做
- Phase 0 授权确认
- 静态 + 动态双重验证
- 记录请求/响应证据
- 危害分级（Critical/High/Medium/Low）
- 元认知反思（偏门思路检查）

### 禁止做
- 未授权第三方目标测试
- 部署武器化工具包
- 伪造漏洞凑数
- 只静态审计不实测

## 六、事件响应

| 事件 | 响应 |
|------|------|
| API Key 泄露 | 立即轮换 + 检查调用日志 |
| 服务器被入侵 | 隔离 → 日志分析 → 重装 → 重新部署 |
| DDoS / 配额耗尽 | 收紧 rate limit + 检查 CORS |
| 依赖 CVE High | `npm audit fix` + 重新部署 |
